# Experiment Paper Grill

一个用于检查 AI 辅助实验与论文写作中科学理解程度的研究评审型 skill。

它的目标是模拟组内交流、导师追问和期刊审稿场景，确认作者真正理解自己准备写进论文的科学内容，并能够对关键实验、方法、公式、结果和结论进行准确解释与辩护。

## 这个 skill 适合什么场景

这个 skill 主要面向以下工作流：

- 实验的一部分由 AI agent 或自动化工具完成；
- 用户知道实验输入和输出，但中间过程存在一定“黑盒感”；
- 论文正文已经包含科学主张，需要确认作者本人理解这些主张并能够解释其依据；
- 论文中出现公式，作者需要理解公式的变量、假设、作用以及与实验之间的关系；
- 学术化表述与具体实现细节处于不同抽象层级；
- 用户希望提前准备导师提问、组内评审、同行评审以及学术诚信层面的追问。

这个 skill 的重点是科学理解，不要求作者机械记忆所有实验数值，也不会默认追问所有工程实现细节。

它主要确认作者是否能够解释：

- 研究问题是什么；
- 为什么当前实验能够回答这个研究问题；
- 方法在科学上的含义是什么；
- 方法依赖哪些假设，又有哪些限制；
- 指标实际测量了什么；
- 实验结果能够支持哪些结论，以及不能支持哪些结论；
- 公式、变量以及它们在论文论证链条中的作用；
- 面对进一步追问时，如何为论文中的科学内容负责并进行解释。

## 按目标期刊校准评审

在正式开始拷打前，skill 会先询问目标期刊、会议或主要学科受众。

得到目标 venue 后，它会优先使用当前、权威的公开资料进行调查，并建立一个针对该 venue 的审稿人画像。调查内容包括：

- aims and scope；
- 相关 article type；
- 作者指南和报告规范；
- 公开的 reviewer / editorial criteria；
- 近期相似论文；
- 该 venue 常见的方法学深度和验证深度；
- 可能的创新性要求；
- 对过度结论的敏感程度；
- 可复现性要求；
- 通常默认读者已经具备的背景知识水平。

评审过程中会明确区分三类信息：

1. 期刊或会议明确写出的正式要求；
2. 从近期同类论文中观察到的常见模式；
3. 基于前两类证据推断出的合理审稿关注点。

如果公开资料不足以支持某种“审稿风格”判断，skill 应当明确说明不确定性，并采用保守的 venue-informed reviewer profile。

### 交叉学科论文的深度校准

对于交叉学科工作，skill 会把主要内容划分为三个层级：

#### Core contribution

直接关系论文创新性、有效性和核心科学结论的内容。

这一部分会进行深入拷打。

#### Supporting technical content

理解或复现实验所需，但不构成主要科学贡献的技术内容。

这一部分重点确认作者理解其科学作用、关键假设和对结果的影响。除非目标期刊通常要求这种深度，否则不会要求用户达到该辅助领域专家级的理论掌握程度。

#### Peripheral domain content

主要作为背景、标准工具、基础设施或辅助实现引入的其他领域内容。

这一部分只确认作者具备负责任使用和准确描述它所需要的理解，不进行与目标期刊实际审稿需求无关的专家级追问。

这种校准可以降低交叉学科论文中的无效拷打。例如，当某个机器学习模型只是科学分析工具时，评审重点会更接近“为什么适合当前科学问题”“引入了哪些假设”“输出如何支持结论”，不会因为模型内部存在复杂结构就自动转向纯机器学习理论考试。

## 核心交互方式

skill 使用严格的一问一答式评审循环。

每一轮会：

1. 先检查用户已经提供的材料，能从材料直接获得的事实不要求用户凭记忆回答；
2. 将问题集中在科学判断、解释、假设、设计理由和结论边界上；
3. 每个问题同时给出一个简短的“推荐回答方向”，说明一个合格作者应该回答到什么深度；
4. 等待用户回答；
5. 根据回答判断理解是否清晰、部分清晰、表面化、错误或仍依赖未检查材料；
6. 只有存在真正未解决的问题时才继续向下追问；
7. 直到当前科学分支形成共享理解。

skill 不要求作者记住所有实验数值，也不会为了“严格”而追问无关的实现细节。

## 黑盒实验检查

当实验主要由 AI agent 或自动化流程完成时，skill 会检查作者是否理解论文真正依赖的科学过程。

重点包括：

- 实验输入是什么；
- 进行了什么科学上有意义的变换；
- 为什么这些变换适合当前研究问题；
- 引入了哪些假设；
- 哪些中间量会影响论文解释；
- 输出在科学上代表什么；
- 输出如何进入后续分析或结论；
- 哪些步骤属于科学上必须掌握的内容；
- 哪些步骤只是工程实现选择。

如果某个中间步骤会改变论文的科学含义，而作者无法解释它，skill 会把它标记为尚未解决的 black-box dependency，并继续追问。

## 论文科学表述检查

评审论文段落时，skill 会重点检查以下边界是否表达清楚：

- 相关性与因果关系；
- 实验观察与理论解释；
- 直接测量量与推断量；
- proxy metric 与真正目标量；
- 算法操作与科学机制；
- 假设与已经证实的事实；
- 统计显著性与实际意义；
- 模型行为与现实世界机制；
- 定性趋势与定量结论；
- 局部实验结果与广泛泛化结论。

如果论文措辞比证据实际支持的范围更强，skill 会优先确认作者本人是否清楚正确的结论边界，再决定是否需要修改文字。

## 实验设计拷打

对于关键实验，skill 会沿着与科学结论有关的决策树进行追问，例如：

- 这个实验具体回答什么研究问题；
- 为什么必须做这个实验；
- 自变量、因变量、控制变量和潜在混杂因素分别是什么；
- baseline 为什么这样选择；
- 比较设计隔离了哪一个假设；
- 数据预处理会不会改变科学解释；
- 方法为什么适合当前问题；
- 指标到底测量了什么；
- 指标改善为什么能够支持论文主张；
- 结果直接显示了什么；
- 哪些解释仍然只是推断；
- 结论是否依赖特定数据集、随机种子、参数、评价指标或实验条件。

skill 不会机械遍历所有可能问题，只会追踪与当前核心 claim 有实际关系的分支。

## 公式理解检查

论文中出现的重要公式默认属于作者科学论证的一部分。

对于这些公式，skill 会确认作者能否解释：

1. 公式解决什么问题；
2. 每个符号代表什么；
3. 必要时，各变量的维度、定义域或数据类型；
4. 哪些量是测量得到的、估计的、优化的、假设的或推导得到的；
5. 为什么采用这种数学形式；
6. 公式依赖什么假设；
7. 公式如何连接到具体实验；
8. 公式输出如何进入后续流程；
9. 关键变量增大、减小、趋近于零或进入极限情况时会发生什么；
10. 该公式属于定义、目标函数、估计器、近似、变换、物理定律、统计模型还是推导结果。

如果论文并不依赖完整数学推导，skill 不会强制要求形式化证明。如果推导本身构成方法合理性或论文贡献的一部分，则会提高理解要求。

## 结果与结论分层

对于重要结果，skill 会区分：

### Observation

实验直接测量或观察到了什么。

### Analysis

这些观测值经过了什么处理和汇总。

### Interpretation

作者认为这些结果意味着什么。

### Mechanism

是否有证据解释结果为什么发生。

### Generalization

结论预计可以扩展到哪些范围。

### Limitation

结论在哪些情况下可能失效。

这种分层用于防止论文把“观察到某个结果”“推测其原因”和“证明了某个机制”混在一起。

## Reviewer simulation

评审过程中，skill 会根据目标期刊的公开信息和近期论文，模拟较合理的审稿压力，例如：

- 导师要求作者解释方法为什么成立；
- 组内成员挑战关键假设；
- 审稿人追问实验有效性；
- 审稿人要求说明指标为什么能够支撑结论；
- 审稿人提出替代解释；
- 审稿人要求解释公式的科学含义；
- 审稿人询问什么样的结果能够证伪当前解释。

这里模拟的是 venue-informed reviewer priorities，不声称能够预测具体真实审稿人的个人偏好。

## 学术诚信边界

这个 skill 不会把“使用 AI 辅助完成实验或论文”本身视为学术不端。

它关注的是作者能否对最终选择写入论文的科学内容负责。

以下情况会被视为较严重的作者理解风险：

- 论文核心 claim 作者本人无法解释；
- 关键实验对作者仍然是科学意义上的黑盒；
- 论文包含作者无法说明含义的公式；
- 实验结果被解释得比证据实际支持的程度更强；
- AI 生成的科学解释未经作者验证就直接进入论文；
- 作者无法解释关键方法选择的理由；
- 论文把尚未获得实验支持的机制描述为已经证实的事实。

遇到这类情况时，skill 会明确指出风险，并继续处理相关科学分支。

## 推荐使用方式

### 1. 论文段落评审

提供论文正文，以及与该段内容相关的实验说明、图表、代码、日志或输出。

例如：

> 我的目标期刊是 [期刊名称]。先调查这个期刊，然后按照该期刊可能出现的审稿深度和风格，拷打我这一段论文中的科学内容。

### 2. 黑盒实验理解

提供 agent 生成的实验材料、配置、代码、日志和输出。

例如：

> 这个实验主要由 AI agent 完成。我知道输入和结果，但中间过程还有黑盒。请一直拷打到我能够按照论文要求科学地解释这个实验。

### 3. 公式理解

提供公式、论文上下文，以及必要时对应实现代码。

例如：

> 拷打我这个公式，直到我能够解释每个符号、假设、科学作用以及它和实验之间的关系。

## 使用理念

AI 辅助并不会降低作者对论文内容的理解责任。

这个 skill 的目标是让作者对最终发表的科学叙述拥有足够清晰的理解，同时避免把精力浪费在对论文结论没有实际影响的工程细节或跨学科边缘知识上。

代码实现和论文学术表述可以位于不同抽象层级。只有当两者之间的差异会实际影响科学有效性、可复现性、解释、假设或结论时，skill 才会把它作为需要处理的问题。

## 思路来源

这个 skill 继承了 `grill-me` / `grilling` 类型 agent skill 的核心交互思想，包括：

- 持续追问；
- 一次只问一个问题；
- 能从已有环境和材料查到的事实优先自行检查；
- 按依赖关系逐层解决决策树；
- 在形成共享理解前，不急于进入实现阶段。

当前版本进一步针对以下场景进行了专门化：

- AI 辅助实验理解；
- 科学论文答辩式检查；
- 公式理解；
- 目标期刊校准；
- 交叉学科审稿深度控制；
- reviewer simulation；
- 学术诚信风险检查。
